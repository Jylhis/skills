# Resume / CV structure

A tailored resume reorders and rephrases the candidate's real history to match a
specific posting. It never invents experience.

## Recommended sections (top to bottom)

1. **Header** — name, one-line title matched to the target role, location
   (city/region or "Remote"), email, phone, LinkedIn/portfolio/GitHub.
2. **Summary** (optional, 2–3 lines) — who the candidate is and the value they
   bring, phrased toward the posting. Skip it if it would only restate the header.
3. **Experience** — reverse-chronological. Each role: company, title, dates
   (month/year), then 3–6 bullets.
4. **Skills** — grouped (e.g. Languages, Tools, Domains). Mirror the posting's
   terminology where truthfully applicable.
5. **Education** — degree, institution, year. Move above Experience only for
   recent graduates.
6. **Optional** — certifications, publications, open-source, talks, when relevant
   to the role.

## Writing the experience bullets

- **Impact first, then how.** "Cut checkout latency 40% by …" beats
  "Responsible for performance work."
- **Quantify** wherever a real number exists (%, $, time, scale, team size).
- Start with a strong past-tense verb; drop "responsible for" and "helped".
- One line each where possible; two only when the impact needs it.
- Foreground the bullets that map to the posting's must-haves (from Phase 1).

## Tailoring rules

- Reorder bullets and roles so the most relevant experience is highest.
- Adopt the posting's vocabulary for skills the candidate genuinely has (first-pass
  filters are often keyword matches — see `gotchas.md` on ATS).
- Cut content irrelevant to this role to keep length tight (1 page early-career,
  2 pages for extensive experience).
- Never add employers, titles, dates, degrees, or metrics that are not real. If a
  gap or mismatch exists, raise it as a question.

## Format

- Clean, single-column, standard fonts; no tables/columns/graphics that ATS
  parsers choke on (see `gotchas.md`).
- Consistent date format and tense throughout.
- Deliver as `.docx` or Markdown per the candidate's preference.
